# K-BOX 问学知识平台视频系列：内容主线规划

> 维护入口：本仓库 planning/。2026-11-02 从产品文档迁入，后续在此更新。

> 编写日期：2026-11-01  
> 状态：初版，供讨论和后续选题拆分使用。  
> 本文是视频系列的主线规划入口，后续单条选题、脚本和制作安排均以此为依据。

配套目录：[分类与选题规划](K-BOX视频系列-分类与选题规划.md)。主线说明内容覆盖范围；配套文档按“认知与选型、任务实操、细节专题、诊断与优化”维护本轮讨论的 50 个已编号主题及待细化范围与分类边界，后续选题以该目录为准。

## 1. 系列目标与约束

围绕 K-BOX 问学知识平台，建设覆盖客户认知、能力选型、实际操作、效果优化、开发集成和企业交付的视频系列。整体规模为**几十条独立专题视频，每条成片时长必须为 2–7 分钟**，从平台全景逐步深入具体操作、原理和细节。

已明确的要求：

- **覆盖全部主要受众**：客户与售前、产品与架构人员、终端使用者、知识运营与实施人员、开发者、管理员与运维人员；通过分类和观看路径组织，不要求所有人按同一顺序看完。
- **一条视频解决一个核心问题**：观众看完能够作出一个判断、完成一个操作，或排查一种问题。
- **每条均为 2–7 分钟**：前置说明、操作、结果验证和片尾均计入成片时长。超出 7 分钟时先精简范围和配置分支，任务实操保留业务闭环；确需拆分则重新定义各片的完整目标。不足 2 分钟且没有独立学习价值的操作合并到相关主题。
- **单条可独立观看，主线内可以连续学习**：必要前提在片头简要说明，深入内容通过关联视频衔接。
- **围绕当前可验证的产品能力制作**：规划、原型、工作区实现和录制环境中的可用功能分别核对，不将未来能力作为现成功能演示。

本文确定内容主线、范围与学习结果，下文示例用于说明拆分方向。单条主题和预计时长已集中在配套目录维护，本轮先收敛分类和主题；脚本、素材细化与录制顺序在目录收敛后安排。

## 2. 贯穿全系列的产品叙事

**业务问题 → 知识与数据接入 → 理解和处理 → 组织与治理 → 检索、阅读、推理和问数 → 向人和智能体供给可信知识 → 验证与持续维护。**

系列重点解释：企业已有资料和数据，怎样经过 K-BOX 成为可理解、可检索、可授权、可追溯的知识服务。各模块都应回到它解决的业务问题和可验证结果。

对外可通过文档知识库、企业 Wiki、知识图谱和数据洞察介绍主要能力；深入教学时补充问答对库、术语库等具体载体。需要保持以下概念边界：

- 文档库、Wiki、图谱按所需知识产物选择，可以组合使用；三者之间没有固定升级顺序。
- 数据主题服务结构化数据查询，不应讲成知识空间下的一种文档库。
- 知识处理完成、检索命中、回答有依据，是不同验收环节。
- 管理知识的权限与消费知识的权限分别说明，通过具体身份和调用结果验证。
- 平台内智能体应用与外部 Agent 接入，分别解释编排职责、工具范围和权限边界。

## 3. 内容主线总览

主线使用稳定编号 A–L。每条主线下包含多条短视频；主线编号用于描述内容范围，不代表必须依次录制或观看。A 承担全平台导览，B 承担跨能力上手路径；单条视频另外记录主要能力主题和一个主分类，避免将学习路径与产品模块混为互斥分类。

| 编号 | 内容主线 | 核心问题 | 主要受众 |
| --- | --- | --- | --- |
| A | 平台认知与能力选型 | K-BOX 解决什么问题，应该选择什么能力？ | 客户、售前、产品、架构师 |
| B | 首次上手与完整任务 | 如何从零完成一次有结果的体验？ | 使用者、实施、初次接入的开发者 |
| C | 知识组织与来源接入 | 知识如何分类、接入并持续维护？ | 管理员、知识运营、实施 |
| D | 文档处理与信息提取 | 原始文件如何成为可用知识或结构化结果？ | 知识运营、实施、开发者 |
| E | 检索、问答与效果优化 | 怎样找到正确证据、生成可靠回答并定位问题？ | 使用者、实施、开发者 |
| F | 企业 Wiki 与知识沉淀 | 怎样把分散资料沉淀为可阅读、可维护的主题知识？ | 知识运营、使用者、实施 |
| G | 知识图谱与关系探索 | 怎样构建、治理和复用实体关系及证据？ | 知识工程师、实施、架构师 |
| H | 数据洞察与业务语义治理 | 怎样让自然语言查询符合真实业务口径？ | 业务分析、数据治理、开发者 |
| I | API、MCP、Skill 与开发集成 | 怎样把 K-BOX 知识能力接入外部系统和 Agent？ | 开发者、架构师、实施 |
| J | 权限、安全与企业管理 | 谁能维护什么，谁能消费什么，如何验证？ | 管理员、架构师、实施 |
| K | 模型配置、部署与持续运营 | 怎样配置依赖、完成交付并保持系统可用？ | 管理员、运维、实施 |
| L | 本体建模与进阶语义 | 怎样表达并复用业务对象、关系和规则契约？ | 架构师、知识工程师、进阶实施 |

## 4. 各主线的范围与拆分方向

### A. 平台认知与能力选型

**学习目标**：理解知识就绪层的价值，判断 K-BOX 与已有文档系统、数据平台、模型平台和 Agent 平台的分工，为真实业务问题选择合适的知识形态与接入方式。

覆盖产品定位、能力地图、知识载体选型、典型场景、企业级保障、项目首次验证方法与开发者文档使用。重点回答“为什么需要”和“什么时候选择”。

可拆分主题示例：《问学知识平台基础介绍》《已有文档系统，为什么还需要 K-BOX？》《文档库、Wiki、图谱怎么选？》《API、MCP、Skill 怎么选？》。问答对、术语与数据洞察的选型也应在本主线中有明确位置。

**与其他主线的衔接**：A 解释价值和选择依据；B 展示最短完整体验；C–L 承接各领域操作和细节。

### B. 首次上手与完整任务

**学习目标**：观众用少量代表性资料，在已有必要模型、账号和环境的条件下，完成一条可核验的业务链路。

覆盖首次文档问答、首次 Wiki 生成与阅读、首次图谱构建与验证、首次自然语言问数、首次外部 Agent 接入。每条先展示目标结果，再完成必要操作，最后核验。

可拆分主题示例：《从一份手册到第一个带引用的回答》《从分散资料到企业 Wiki》《完成第一次自然语言问数》。任务预计超过 7 分钟时，先缩小案例并把公共配置移至细节专题，保留从输入到使用、结果核验的闭环；确实无法容纳时重新讨论范围。

**与其他主线的衔接**：本主线是跨能力的上手入口。配置原理、参数比较和异常排查交给对应主线，不在每条上手视频中重复铺开。同一成片只维护一份，可同时归入角色观看路径。

### C. 知识组织与来源接入

**学习目标**：为实际业务设计可维护的知识结构，选择合适的内容载体与来源，并理解知识更新、启停和删除的影响。

覆盖租户、空间、目录与库的关系，部门或项目知识分类，问答对、术语、标签，外部知识来源同步，以及内容有效期、禁用与回收站。集成示例优先采用已验证的飞书链路。

可拆分主题示例：《空间与目录分别管什么？》《维护一组标准问答》《用术语库统一别名》《用标签缩小检索范围》《飞书知识如何同步与更新？》。

**与其他主线的衔接**：C 负责内容组织、接入和生命周期；文件内部处理进入 D，权限配置与验证进入 J。空间主要承载向量化方案，不默认按部门各建一个空间。

### D. 文档处理与信息提取

**学习目标**：理解文件经过哪些处理才能使用，按资料特征配置解析与切片，并检查处理产物或结构化提取结果。

覆盖处理状态、解析器、扫描件与图文混排、分段策略与大小、标题和文件名关联、Excel 表格、图片理解、音视频转写、文档摘要、文件轨迹，以及按模板提取指定字段。

可拆分主题示例：《上传成功，为什么还不能问答？》《自动、语义、按页分段怎么选？》《Excel 怎样入库才查得到？》《用文件轨迹定位解析失败》《从合同中提取指定字段》。

**与其他主线的衔接**：D 核查处理结果是否完整可用；处理后仍检索不到或回答不对，进入 E。信息提取与临时文件解析按各自流程制作，不混同于建库问答。

### E. 检索、问答与效果优化

**学习目标**：区分检索和回答，能够验证证据、定位效果问题，并用固定问题对照优化。

覆盖全文、向量与混合检索，TopK、重排、标签与范围过滤，命中测试，上下文补全，Agentic RAG 多轮检索，引用与原文核验，以及小型验收题集的建立。

可拆分主题示例：《关键词、向量与混合检索怎么选？》《TopK 越大越好吗？》《用命中测试定位答非所问》《有引用就代表答案可靠吗？》《跨文档问题怎样补充检索？》。

**与其他主线的衔接**：E 以文档检索与知识问答为主，提供通用的效果分析方法；Wiki、图谱和数据洞察的专属链路在 F、G、H 讲解。验收题集可以用独立清单管理，不暗示平台已有完整评测产品。

### F. 企业 Wiki 与知识沉淀

**学习目标**：理解 Wiki 页面与原始文档、即时问答的关系，完成主题知识的阅读、核查、更新与维护。

覆盖页面生成、文档页与实体/概念页，导航和页面链接，搜索与全文阅读，来源回读，编辑与修订，源文档更新，以及冲突内容处理。回答归档与知识缺口研究按录制环境验证情况再安排。

可拆分主题示例：《Wiki 与文档问答分别沉淀什么？》《页面怎样回到原始来源？》《两份资料说法冲突怎么办？》《源文档更新后如何检查页面变化？》。

**与其他主线的衔接**：F 负责可阅读知识的持续沉淀。页面链接图与 G 的实体关系图分别解释；自动生成和发布不等于业务权威口径已经审核确认。讲解时区分“企业 Wiki 库”与“K-BOX 开发者文档站”。

### G. 知识图谱与关系探索

**学习目标**：判断显式关系建模的必要性，构建与核查实体关系，并通过关系探索和原文证据支持回答。

覆盖适用场景、灵活与严格模式、图谱模型、消歧词库、实体与关系抽取、来源和抽取质量、多跳探索、证据回读、图谱维护与问题排查。

可拆分主题示例：《什么时候值得建设图谱？》《灵活模式与严格模式怎么选？》《图谱模型与消歧词库怎样配合？》《一条关系怎样核对原文？》《多跳探索怎样形成证据链？》。

**与其他主线的衔接**：G 负责关系事实的构建和使用；业务契约与规则定义进入 L。跨文档问答先验证 E 的多轮检索，按实际需要决定是否建设图谱。

### H. 数据洞察与业务语义治理

**学习目标**：把数据库结构和业务口径整理为可用语义，完成问数并核验 SQL 与实际结果。

覆盖只读数据源、数据主题初始化、表字段语义、业务概念、指标与维度、统计粒度、表关系、过滤值、多轮问数、结果表与图表、查询历史和 Query Memory。

可拆分主题示例：《问数为什么需要业务语义？》《表字段治理与业务概念怎样分工？》《为什么 SQL 能执行，业务结果却不对？》《同名指标如何明确口径？》《正确查询怎样沉淀为查询记忆？》。

**与其他主线的衔接**：H 负责问数和语义治理；通过外部 Skill 调用的安装与接入进入 I。查询成功与业务正确分别核验，数据库只读账号与应用校验分别说明。数据库方言、跨库和分析范围以录制环境验证结果为准。

### I. API、MCP、Skill 与开发集成

**学习目标**：根据调用方选择接入入口，完成授权、资源发现、调用与来源核验，理解平台与外部 Agent 各自职责。

覆盖首次 Open API 调用、检索服务与直接检索、上下文与原文读取、MCP 接入、Skill 中心及能力包导出、不同资产的工具流程、临时文件解析与信息提取接口。

可拆分主题示例：《完成第一次检索 API 调用》《通过 MCP 让 Agent 检索企业知识》《创建并导出一个 Skill》《文档、Wiki、图谱 Skill 有什么区别？》《不建库，怎样解析临时文件？》。

**与其他主线的衔接**：I 负责能力供给与调用契约，不按接口数量机械制作视频。不同入口的覆盖范围、身份传递和运行依赖分别验证；密钥、协作和内容访问规则的完整说明进入 J。本体离线快照 Skill 的语义与版本内容进入 L。

### J. 权限、安全与企业管理

**学习目标**：分清登录角色、资源管理与内容消费等权限维度，通过不同身份实际验证授权结果。

覆盖租户与角色、创建者和协作者、目录继承、公开/内部/私有访问级别、企业用户和组织、单点登录、API 密钥、终端用户身份、模型与凭证可见性、调用记录。

可拆分主题示例：《能管理知识库，为什么还检索不到？》《公开、内部、私有怎样验证？》《给同事协作权后，他能做什么？》《API 密钥与终端用户身份怎样共同生效？》。

**与其他主线的衔接**：J 集中解释权限规则与验证方法。其他实操片只交代本任务需要的身份和资源，不反复展开整套权限模型。各资产和入口的权限规则分别核查。

### K. 模型配置、部署与持续运营

**学习目标**：准备可用模型和基础设施，完成上线走查，观察运行成本与状态，并定位依赖或系统故障。

覆盖 Chat、Embedding、Rerank、多模态和 ASR 的用途，模型与凭证配置、连通性测试，私有化组件与依赖、解析服务、内网交付、部署后检查、队列与重试、轨迹和调用记录、模型用量与知识储量统计。

可拆分主题示例：《问答前需要配置哪些模型？》《Embedding 和 Rerank 分别做什么？》《新环境怎样完成全链路走查？》《模型调用失败如何定位？》《怎样看懂模型用量？》。

**与其他主线的衔接**：K 负责共享依赖、运行与交付；D、E、F、G、H 负责各领域内容和结果问题。模型用量、知识储量和回答质量是不同指标，分别解释。

### L. 本体建模与进阶语义

**学习目标**：区分业务语义契约、事实关系、标准词和查询口径，理解本体的定义、协作、发布和复用方式。

覆盖本体与图谱/术语/概念的关系，业务类、关系、规则、行动与决策模型的定义，校验、草稿、分支与发布版本，以及已发布契约的 Skill 快照导出。具体功能是否可演示，以录制环境核验为准。

可拆分主题示例：《本体、图谱、术语有什么区别？》《为一个业务域定义类与关系》《草稿、分支和发布版本怎样协作？》《把已发布本体交给外部 Agent》。

**与其他主线的衔接**：L 属于进阶内容，不作为首次建库的前置条件。本体定义、规则执行、实例图谱和业务自动化分别说明，不能由定义界面推导出已具备完整执行能力。

## 5. 从宏观到细节的拆分方式

每条主线根据需要采用以下分类，不要求每项能力机械凑齐四类视频。具体定义与主题目录见[分类与选题规划](K-BOX视频系列-分类与选题规划.md)，本轮围绕该目录逐项讨论：

| 层次 | 单条视频的结果 | 建议成片时长 | Wiki 示例 |
| --- | --- | --- | --- |
| 认知与选型 | 理解价值，判断适用性 | 3–5 分钟 | Wiki 与文档问答怎么选 |
| 任务实操 | 从资料或需求到实际使用与结果核验形成闭环 | 4–7 分钟 | 从源资料到 Wiki 页面、问答与来源核验 |
| 细节专题 | 理解并用好一个机制或参数 | 2–7 分钟，优先 2–5 分钟 | 页面引用怎样回到来源 |
| 诊断与优化 | 定位一种问题并验证改进 | 3–7 分钟 | 两份资料口径冲突怎样维护 |

任务实操集中为 8 个业务闭环。操作难以在 7 分钟内完成时，优先缩小样例、减少分支，把模型、接口和参数等公共配置交给细节专题；保留关键操作、实际使用和结果核验。不能仅为缩短视频，就把建库和使用默认拆成两条任务片。

异步处理可以剪辑等待时间，但要注明等待或加速，保持实际处理过程和成片时长的区别。专题拆分不应把一个开关或一次点击当作唯一理由。

## 6. 观看路径与主线衔接

| 观众 | 推荐路径 | 观看目标 |
| --- | --- | --- |
| 客户、售前、产品 | A → B 中相关体验 → F/G/H 中相关认知 → J/K 中企业保障 | 判断价值、适用场景与落地条件 |
| 终端使用者 | A 中能力选择 → B → E/F/H 中阅读、提问与结果核验 | 开始使用并判断答案是否可靠 |
| 知识运营、实施 | A → B → C/D/E → 对应 F/G/H → J | 建设、维护和优化知识资产 |
| 开发者、架构师 | A → I → 对应 E/F/G/H → J/K；按需进入 L | 完成集成，理解职责与技术边界 |
| 管理员、运维 | K 中环境与模型准备 → J → C → B 中验收 → K 中持续运营 | 准备环境、授权和交付运营 |

B 是任务入口，C–L 是深入学习路径。跨主线主题只选择一个主归属，通过关联链接复用，避免同一操作在多条视频中完整重复。

## 7. 贯穿案例

| 案例 | 准备内容 | 适用主线 | 重点验证 |
| --- | --- | --- | --- |
| 企业制度与员工服务 | 制度正文、FAQ、旧版本、部门标签、不同访问角色 | B/C/D/E/F/J | 原文依据、标准答案、更新与冲突、访问范围 |
| 产品—供应商—资质 | 少量相互关联的文档，明确实体、关系和来源 | B/G/L | 别名、关系事实、探索路径、业务契约 |
| 客户—订单—回款 | 合成数据库，包含一对多关系、时间范围和指标口径 | B/H/I | 统计对象、连接与聚合、口径、结果复核 |

每套案例维护正常题、无答案题、权限题，以及冲突或错误结果对照。案例尽量跨片复用，让观众持续理解同一批资料在不同能力中的变化。

## 8. 后续落地方式

1. **按分类维护单条主题**：按配套目录使用 `N01`（认知）、`T01`（任务）、`S01`（细节）、`R01`（诊断）等编号，另行记录 A–L 对应内容范围、主要能力主题、目标观众、唯一核心问题、学习结果、预计成片时长与前置视频。编号与排期分离，新增后保持稳定。
2. **先形成主干观看路径**：利用已完成的基础介绍试片，优先补齐能力选型、文档问答上手、命中测试、来源核验，再覆盖 Wiki、图谱、问数、外部接入与权限。录制顺序另行安排，不按 A–L 一次性顺排。
3. **按录制版本核验内容**：记录环境、日期与相关功能版本；文档和界面存在新旧差异时核查实际行为。知识源集成、Skill、本体和新增处理功能尤其需要确认。
4. **编写脚本与分镜**：采用“目标结果 → 前提 → 讲解或操作 → 核验”的结构。配音、字幕、屏幕重点和预计时长同步编排，保证单条 2–7 分钟。
5. **保存可维护素材**：保留选题卡、脚本、案例资料、录屏、配音、字幕与功能依据。界面变化时可以更新相关片段，不需要重做整个系列。

现有《问学知识平台基础介绍》v3 时长约 3 分 52 秒，作为 A 主线的首条候选成片；已覆盖产品定位、产品能力、知识消费、应用场景、企业级保障和文档中心。
