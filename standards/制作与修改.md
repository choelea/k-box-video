# 制作与修改

## 内容源与编号

视频只设一个主分类：N 认知与选型、T 任务实操、S 细节专题、R 诊断与优化。编号一经分配保持稳定。同一主题可以出现在多个观看路径中，制作源文件只维护一份。

planning/ 是系列选题维护源，单集场景归入 episodes/<编号>/；distribution/ 保存官网等渠道的接入与发布说明，迁移及历史恢复记录归入 reports/history/。k-box-docs 中的视频规划与发布说明副本已清理，仅通过 README 链接到本仓库；后续不在产品文档仓库新建视频制作副本。

每条项目以 episode.json 记录目标、状态、时长、产品版本和待修项。当前配音文本源是 source/plan.json，讲解稿.md 供人阅读和讨论，修改后须保持一致。分段文本与已存音频通过 source/narration-manifest.json 绑定；修改配音源后刷新绑定，不能读取旧版目录作基准。验收报告和截图放 review/，修订日志放 review/revisions/；具体目录规则见 [目录与版本管理](目录与版本管理.md)。生成的字幕与时间线允许人工精修，但须记录并保留同步关系。

## 分镜与素材

新视频使用 templates/episode/ 选题卡和分镜表。每个镜头分配固定编号，如 N03-S01；关联讲解段、素材路径、实际操作证据和时长。将“哪些内容需要展示”与“精确剪辑时点”分别记录。

原始录屏放 assets/recordings/；截图放 frames/；配音放 audio/。全部使用项目相对路径。MP4、WebM、WAV、MP3 和位图通过 Git LFS 保存。构建缓存可丢弃，唯一素材不得放 build/。

初期沿用已有合成脚本。修改配音可能改变时长，必须重新计算字幕与分镜；不承诺修改文本后所有镜头已能自动对齐。

## 修改流程

1. 确认这次修改的脚本、画面或发音范围，保存值得保留的旧版本。
2. 修改内容源，更新受影响配音、字幕、分镜与图解。
3. 重新合成，执行技术检查，再核听和核对画面证据。
4. 更新素材清单、episode.json 和制作记录，提交一次完整修改。
5. 审阅通过后记录发布版本；没有发布或上传动作时，不写成已经发布。

N02 使用现有公开售后知识库，深度模式，本集不展开权限。业务输入是标明的假设，不能描述为查询出的真实故障数据或已执行的处置。
