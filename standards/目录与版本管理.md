# 目录与版本管理

本规则维护视频内容与制作文件的边界。问学是上位品牌，K-BOX / 问学知识平台是本系列介绍的产品。

## 全仓分类

| 目录 | 保存内容 | 不放什么 |
| --- | --- | --- |
| planning/ | 系列主线、分类、选题目录 | 迁移日志、单集实际问答与录屏 |
| standards/ | 命名、发音、视觉、制作、验收及文件规则 | 具体视频的口播稿 |
| shared/ | 已确认品牌基线、公共图标和样式、参考音与审批证据 | 多份完整单集项目 |
| templates/ | 新集空白模板 | 已制作的视频素材 |
| episodes/ | 按固定编号维护每集当前完整项目 | 每次修订的完整目录复制 |
| distribution/ | 官网与其他发布渠道的接入、更新与验证说明 | 单集制作源文件的第二份副本 |
| reports/ | 全仓盘点、重复检查、整理规划；history/ 保存迁移与恢复记录 | 单集正在使用的剪辑配置 |
| tools/ | 两集以上复用的执行工具 | 一集特有的业务判断或剪辑锚点 |

## 每集分类

```text
episodes/Nxx/
  README.md                  单集内容、操作入口和待办说明
  episode.json               编号、状态、当前交付路径与版本
  选题卡.md / 场景方案.md     单集前提、学习结果与业务证据
  分镜.md / 讲解稿.md         便于阅读讨论的版本
  <成片>.mp4 / .srt / .mp3    当前交付物
  poster.jpg / 试看.html      当前封面与播放器
  source/                    制作脚本与配置：plan、时间线、镜头、场景、配音绑定
    snapshots/               作为事实依据的页面文字快照
  assets/recordings/          被当前制作或证据元数据引用的原始录屏
  audio/                     分段 MP3、词边界、请求参数和剪辑 WAV
  frames/                    当前制作、证据回读和录制校准使用的画面
    snapshots/               来源网页截图
  review/                    验收、播放、同步、听音位置等核验记录
    frames/                  当前验收截图、联系表、播放器检查截图
    revisions/               单集各次修订的文字记录，不复制整集媒体
  build/                     合成片段、ASS、章节元数据等可再生本地缓存
```

不为每个新视频机械创建所有可选文件。单集根目录保留交付物，避免改变现有播放器与官网发布流程。`source/plan.json` 是讲解唯一维护源；阅读稿、字幕及时间线是生成产物或用于精修的对应文件，不分别修改出第二套讲解。

## 重复与保留规则

以 SHA-256 判断完全相同内容，不以文件名相似判断可删除。MP3 与 WAV 分别服务音频留存和剪辑；正式文本、发音辅助、词边界与配音绑定各有用途，不算冗余。品牌试听 A–D 是试验依据，C 是已确认参考，保留各自说明。

公共样式统一为 `shared/brand/v0.1/visual/base.css`；片头、图解模板与各集 HTML 引用它。`tokens.json` 是人工维护的参数说明，尚未自动驱动 CSS；更改风格时两者须同步，生成样片并审阅。公共截图入口为 `tools/capture-brand.cjs`，各集只维护自己的 scenes.json 和局部样式。

同一原文可对应多个解释位置，同一核听语句也可同时作为参考与单集片段。此类确有用途的完全相同文件在 [保留重复内容](保留重复内容.json) 中记录原因；后续若文件分化，审查并更新名单。工具遇到新的重复组会要求人工判断，不自动删素材。Git LFS 对相同媒体内容只存一份对象。

## 历史与清理

历史通过 Git 提交保存，不再维护 archive/ 工作目录。旧项目恢复方法见 [历史记录](../reports/history/历史版本.json)。历史文档中原先的 archive 路径仅表明当时存放位置，不参与当前构建。

删除旧素材之前，必须确认当前脚本、分镜、证据和校准流程不再使用，且 Git/LFS 中存在可恢复内容；在清理记录中保存路径、哈希、原因及恢复提交。不得把原片、唯一源文档或登录状态当作缓存处理。删除工作区文件不会自动减小远端历史或 LFS 存储，不改写已有提交历史。

`build/` 可以从保留素材重建。验收图片保留当前镜头的一套，旧版检查图可依 Git 恢复；本次文件移动或清理必须同步素材清单与脚本输出位置。清理后执行全仓审计、分集素材检查和必要的离线导出。

## 后续顺序

1. 每集先有选题卡、业务场景、明确的学习结果，再创建制作目录。
2. 文本定稿后生成配音绑定、时间线、字幕与分镜，接入公共品牌样式。
3. 录屏与证据分别检查，成片检查结果写入 review/；episode.json 保持实际审阅状态。
4. 新功能或新镜头出现后再提取通用工具，不一次性把所有剪辑脚本改造成框架。
5. 内容审阅通过后再记录发布版本；发布副本及官网部署由 distribution/ 管理。
