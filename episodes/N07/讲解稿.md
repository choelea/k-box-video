# N07 · API、MCP、Skill，怎样选择接入路径？

> **分类**: 认知与选型  
> **预计时长**: 4-6分钟  
> **录屏素材**: K-BOX Skill 中心、MCP 服务、Open API 控制台

---

## 开场 (0:00 - 0:15)

欢迎了解问学知识平台。今天我们来聊一个在集成时经常被问到的问题：API、MCP、Skill 三种接入方式，应该选哪一个？

---

## 为什么需要外部接入 (0:15 - 0:50)

K-BOX 本身已经提供了完整的知识管理和问答能力。但在很多企业场景中，业务系统、客服平台、内部工具也需要使用这些知识。

比如，企业自研的 CRM 系统需要在客户详情页展示相关知识；智能客服机器人需要调用企业知识库回答售后问题；内部 Agent 需要检索合同条款来辅助审批。

这些场景都需要把 K-BOX 的知识能力接入到外部系统。平台提供了三种接入方式：Open API、MCP 协议和 Skill。

---

## Open API：精确控制的程序化调用 (0:50 - 1:35)

Open API 是最基础的接入方式。平台把检索、问答、文件管理等能力封装成标准 HTTP 接口，外部系统通过 API Key 调用。

它的优点是精确可控：调用方可以指定查哪个库、过滤什么标签、返回多少片段、要不要带原文。适合对接口行为有明确要求的系统集成，比如自研 CRM、ERP、工单系统。

调用流程通常是：获取 Token、发起检索请求、解析返回结果、在自己的业务逻辑中使用。平台侧只负责检索和返回，如何使用结果由调用方决定。

---

## MCP：让 Agent 自动发现和调用 (1:35 - 2:20)

MCP 是一种专为 AI Agent 设计的协议。如果你的系统已经在使用大模型 Agent，比如 Claude Desktop、Cursor、或者自建的 Agent 框架，MCP 可以让 Agent 自动发现 K-BOX 提供的工具，并按需调用。

它的特点是不需要预先写死调用逻辑。Agent 根据用户提问的内容，自动判断是否需要调用 K-BOX 的检索工具、调用哪个库、传什么参数。适合需要灵活组合多个工具的对话场景。

MCP 和 Open API 的区别在于，Open API 是"我告诉系统怎么查"，MCP 是"Agent 自己决定要不要查"。

---

## Skill：打包成可复用的能力单元 (2:20 - 3:10)

Skill 是另一种思路。它把一组知识资源和调用规则打包成一个能力单元，可以被内部或外部的智能体使用。

在 Skill 中心，你可以创建一个 Skill，绑定指定的知识库、Wiki 库或图谱库，并配置调用范围和权限。创建完成后，可以导出给外部 Agent 使用，也可以在平台内部多个智能体之间共享。

Skill 的价值在于封装和复用：一次配置、多处使用，并且可以通过版本管理持续维护。适合把"某类业务知识服务"标准化输出给多个调用方。

---

## 三种方式对比：怎么选 (3:10 - 4:00)

简单对比三种方式：

Open API 适合程序化集成，调用方需要精确控制检索参数和返回结构，比如业务系统对接、数据同步。

MCP 适合 AI Agent 集成，Agent 自主决定何时调用、查什么内容，适合对话式场景和多工具组合。

Skill 适合能力封装和复用，把一组知识资源和调用规则打包，标准化输出给多个使用方。

如果你的系统是自己开发的，用 Open API 最直接；如果已经有 Agent 框架在用，优先用 MCP 接入；如果想把某类知识能力标准化输出，就做一个 Skill。

## 小结 (4:45 - 5:10)

API、MCP、Skill 三种接入方式分别对应三种使用场景：程序化集成、Agent 自主调用、能力标准化复用。

选择的关键不是"哪个更好"，而是"谁在用、怎么用、用在哪里"。根据调用方的身份和运行条件选择合适的方式，才能把 K-BOX 的知识能力真正融入业务系统。
